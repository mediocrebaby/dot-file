# gpt-with-taste 与 system-prompt 联动

状态：已实现并验证。

## 目标

通过现有 `/system-prompt` 入口，在首次请求前查看 gpt-with-taste 按当前会话配置将要注入的系统提示词。

## 已确认的分工

用户选择优先支持首次请求前预览，并同意对两个插件做以下改动：

- **pi-system-prompt** 增加通用预览入口，打开窗口时收集扩展提供的内容；不包含 taste 的模板或适用规则。
- **gpt-with-taste** 按当前会话、角色、开关和模型提供将要注入的提示词；预览与实际注入共用内容生成逻辑。

本次采用当前配置的预览，不建设完整 provider 请求或工具定义的历史快照功能。

## 行为约定

- 首次发送消息前即可通过 `/system-prompt` 查看 taste 内容。
- 每次打开窗口时重新生成预览；切换模型、taste 开关或会话后，重新打开即使用新状态。
- taste 关闭、没有模型或模型不适用时，预览中不保留此前的 taste 指令块。
- taste 已存在于宿主提示词中时只显示一份；其他扩展的内容保留。
- 预览、计数与复制使用同一文本。
- taste 状态沿用现有的当前会话分支记录；不为预览新增会话记录，不缓存其他会话内容。
- 临时 steering 是非系统消息，不纳入系统提示词预览。
- 两个插件均能独立运行，实际请求注入路径保持原有机制。

## 接口

viewer 在等待空闲、加入原有日期与环境文本后，同步发布 `system-prompt:preview`，参数为 `{ context, prompt }`。

订阅者按注册顺序同步变换 `prompt`，使用 `context` 读取当前会话信息。taste 使用实际注入的启用判断和 `block()` 生成内容，并清理自身上次请求遗留的指令块。完整协议见 `pi/extensions/pi-system-prompt/README.md`。

## 验证

```bash
node --test pi/extensions/gpt-with-taste/preview.test.mjs
```

13 项回归测试全部通过。测试直接加载两个插件的真实注册逻辑；在未实现时，taste 缺失、关闭后残留及通用入口等断言失败。终端函数使用替身，测试覆盖窗口生成与 OSC 52 复制。

另使用本机实际安装的 Pi 扩展加载器、事件总线、主题和终端渲染函数执行首次请求前的预览与复制，确认 taste 内容出现一次、窗口各行宽度正确、未新增会话记录。未发送实际模型请求。

独立审查指出旧 taste 块位于开头时遗留空行的问题，已修复并用开头、中间、结尾及 CRLF 文本的精确等值测试覆盖。`git diff --check` 通过。
