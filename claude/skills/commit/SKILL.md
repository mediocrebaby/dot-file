## 提交模板

<type>([scope]): <description>

### 提交类型(type)

|类型|描述|说明|
|--|--|--|
|feat|新功能|新增某个功能或特性|
|fix|修复 bug|修复了某个问题或 Bug|
|docs|文档更新|仅修改了文档（如 README.md）|
|style|代码风格调整|不影响代码含义的更改（如空格、格式化、缺失分号等），非 CSS 样式|
|refactor|代码重构|既不是修复 bug 也不是添加新功能的代码更改（如变量重命名、代码结构优化）|
|perf|性能优化|提高性能的代码更改|
|test|测试相关|添加或修改测试用例（如单元测试、集成测试）|
|chore|构建/工具/依赖更新|对构建过程或辅助工具和库（如文档生成工具）的更改|
|build|构建系统/外部依赖|影响构建系统或外部依赖的更改（如 npm、webpack、gulp 配置）|
|ci|持续集成|对 CI 配置文件和脚本的更改（如 Travis、GitHub Actions）|
|revert|回滚提交|撤销之前的某次提交|


### 作用域（scope)

作用域可以是代码的某个模块，某个组件，某个版本。当然AI也可以不写作用域。

### 描述 (description)

描述是对要提交内容的精炼表述。

## 工作流程

### 获取改动内容

通过执行 `git diff` 命令了解当前git仓库做了哪些改动。

### 根据内容分类

结合git仓库和改动内容将修改按内容划分出至少一个主题。

### 按分类提交

将划分出来的主题，然后使用 `git commit` 逐个进行提交。

## 不能做

❌ git log 查看提交日志
❌ 提交信息中携带了 主体(body) 和 页脚（Footr)
