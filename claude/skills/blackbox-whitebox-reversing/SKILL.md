# 黑盒分析、白盒落地的逆向流程

## 概述

逆向一个原生目标时，从头静态反编译整个二进制既慢又容易迷失。本流程用黑盒观测先做两件白盒无法替代的事——**缩小靶区**（定位到少数关键函数，不必逆全程）和**采集 oracle 语料**（输入→输出真值向量集）；再白盒还原被锁定函数的精确算法；最后用黑盒语料把重实现验证到字节级对齐。三者构成一个可收敛的闭环，验证通过即落地。

核心因果链：**黑盒观测 = 靶向信号 + 真值预言机；白盒反编译 = 精确算法；重实现 ⨝ 语料 = 收敛判据**。任何一步都不是为了"显得严谨"而存在，缺一环闭环就无法闭合。

## 第 0 步：授权前置（强制，不可跳过）

在采集任何目标行为前，先确认这是获授权的场景。若用户未说明来源与授权，直接询问：目标是自有/CTF/获授权渗透测试，还是学习用途？无法确认授权时，停在纯静态的公开学习讨论，不要驱动目标程序或采集其行为。确认后再进入第 1 步。

## 工作流程

```
[0 授权] → [1 黑盒观测] → [2 靶区定位] → [3 白盒还原] → [4 验证闭环] ⟳
                                              ↑____________________|
                              (不匹配 → 回到 3 修算法，必要时回 1 补语料)
                                          闭环收敛 → [5 落地]
```

阶段 1、2 常交织进行；4 不通过就回 3（算法细节错），语料覆盖不足时回 1 补样本。

### 第 1 步：黑盒观测，建立行为契约与 oracle

不看内部，先把目标当黑盒喂输入、记输出，建立"输入→输出"映射的经验认识，同时把这些配对固化成验证语料。

1. **确定 I/O 面**：目标从哪进（stdin / argv / 文件 / 网络 / 函数参数）、从哪出（stdout / 返回值 / 文件 / 内存）。
2. **构造多样语料**：空输入、单字节、边界长度、全零/全 FF、可打印 vs 二进制、递增序列——用差异化输入逼出算法特征（长度是否影响输出、是否有位置相关性、是否分组、雪崩效应等）。
3. **采集向量**：用 `scripts/oracle_capture.py` 把语料喂给目标并记录 `(输入, stdout, stderr, exit)` 为 JSON。这份 JSON 既是行为真值，也是第 4 步的测试集。
4. **动态观测锁定入口**：对整程序目标，用动态跟踪（`ltrace`/`strace`、调试器断点、Frida hook）观察它调用了哪些库函数、访问了哪些地址、参数长啥样——这直接指向"关键代码在哪"。工具选择见 `references/binary-tooling.md`。

产出：一份 oracle 向量 JSON + 对算法特征的假设 + 若干候选靶区地址/符号。

### 第 2 步：靶区定位，从黑盒信号收敛到具体函数

先定文件，再定函数——不要一上来就随便挑个二进制拖进反汇编器。

**2a 文件级：挑出该拉进 IDA/Ghidra 的可执行文件。** 目标常是一堆文件（app bundle、多个 .so/.dll、固件 dump），第一个决策是"这么多二进制，哪个才含要还原的逻辑"。判据按信号强度：黑盒阶段看到的字符串/常量出现在哪个文件里（近乎决定性）> 哪个文件含加密算法名/常量指纹 > 动态运行时实际加载并命中的是哪个模块。用 `scripts/triage_targets.py` 扫描候选目录并排序，把第 1 步观测到的线索用 `--needle`/`--hex-needle` 传进去：

```bash
scripts/triage_targets.py ./app/lib --needle "signature invalid" --hex-needle 9e3779b9
```

它输出按优先级排序的二进制清单和"建议优先拉进 IDA"的首选。动态信息（`/proc/pid/maps`、`ltrace` 加载的库、Frida `enumerateModules`、命中地址落在哪个模块）是文件级定位的最强佐证，与脚本的静态排序互相印证。

**2b 函数级：在选定文件里锁定函数。** 把第 1 步的动态信号转成静态坐标，只对少数函数做白盒。常用桥接手法：

- **交叉引用字符串/常量**：黑盒里看到的错误信息、magic、魔术常量（如 S-box、CRC 多项式、`0x67452301` 这类哈希初值），在静态反汇编里交叉引用回定位函数。
- **API 断点回溯栈**：在 `malloc`/`memcpy`/`send`/加密库导出函数下断，命中时回溯调用栈找到业务函数。
- **地址↔源码对照**：动态记录的执行地址减去基址得到静态偏移，直接跳到反编译视图对应位置。

详细手法见 `references/workflow.md` 的"黑盒→白盒交接"一节。产出：待还原函数的明确清单（符号名或偏移）。

### 第 3 步：白盒还原，读出精确算法

只对锁定的函数做静态反编译/反汇编，把逻辑翻译成可读伪代码，再翻译成目标语言实现。

- 识别标准算法（对照常量/结构，多数"自研加密"是标准算法的变体或换了常量的 XTEA/RC4/AES/CRC 等）。
- 逐块还原：数据布局、循环边界、位运算、字节序、查表——这些正是第 4 步最常暴露的错处。
- 边还原边落成可运行代码（Python 优先，快），不要憋到最后一次性写完。

### 第 4 步：验证闭环，字节级对齐 oracle

用 `scripts/verify_reimpl.py` 把重实现跑遍第 1 步的 oracle 语料，逐字节比对 stdout。

- 全部匹配 → 算法还原正确，进入落地。
- 有 MISMATCH → 脚本给出首个分歧字节位置；据此回到第 3 步修正（常见：字节序反了、循环差一、忘了最后一步变换、符号扩展、模数错）。
- 若少量输入匹配但边界输入不匹配 → 回第 1 步补更极端的语料再验证。

**只有全部向量匹配才算落地**，"看起来差不多"不算。

### 第 5 步：落地交付

按用户要的形态收尾：

- **可对接客户端/SDK**：把验证通过的重实现封装成库/CLI，保留 oracle 语料作为回归测试。
- **分析报告**：用 `assets/report-template.md` 结构化输出——目标、方法、关键函数、算法伪代码、还原实现、验证结果。

## 脚本用法

`oracle_capture.py` 与 `verify_reimpl.py` 共用同一套输入喂入约定：命令里含 `{}` 则把输入作为 argv 参数替换进去，否则把输入字节通过 stdin 管道喂入。

```bash
# 0) 文件级靶区：从一堆二进制里挑出该拉进 IDA/Ghidra 的那个（第 2a 步）
scripts/triage_targets.py ./app/lib --needle "signature invalid" --hex-needle 9e3779b9

# 1) 黑盒采集 oracle：把语料喂给目标，记录 I/O 向量
scripts/oracle_capture.py --target ./target --inputs corpus.txt -o oracle.json
scripts/oracle_capture.py --target './target --key {}' --inputs corpus.hex --format hex

# 2) 白盒验证：把重实现跑遍 oracle，逐字节比对
scripts/verify_reimpl.py --reimpl 'python3 my_reimpl.py' --oracle oracle.json
```

`--format` 支持 `raw`（每行一个输入）、`hex`（每行 hex，用于二进制/不可打印输入）、`json`（字符串数组）。`verify_reimpl.py` 全匹配退出码 0，否则 1，可直接接入回归。
