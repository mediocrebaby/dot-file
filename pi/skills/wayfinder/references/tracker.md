# Tracker 适配

规划内容与存储位置分离。先看用户指定位置和项目已有指引：仅聊天则不落盘；本地任务不探测外部服务。用户提供外部来源时可按任务读取，发布、更新、认领和关闭各自需要在当前授权范围内。访问权限不等于操作授权。

## 外部来源与发布

- 确实需要外部读写时才发现工具并核对参数，沿用实际标签与状态；不要求固定安装命令或账户。工具缺失时说明缺口，不能虚构读取结果。
- 创建前核对本任务已存在的票据或映射；同一主题延续时保留身份。只更新已授权的字段，不覆盖无关用户内容。
- 有原生 blocking 关系时优先使用；父子关系用于分组，不自动代表阻塞。没有阻塞字段时用具名链接说明依赖。
- 创建成功后记下真实身份再关联。超时或部分失败时，报告已成功项、未知结果和未执行项；先查询核对是否已创建，再补漏。无法确认的操作标为待核对，不盲目重发整批，不擅自删除已成功项作回滚。
- 本地草稿不是已发布 Issue。父 Issue 的修改或关闭必须有针对该操作的授权，笼统的“维护地图”不等于任意关闭父项。

## 本地持久化

已有项目格式和位置优先；缺省使用工作区 `.scratch/<effort>/map.md`、`issues/<NN>-<slug>.md` 与 `spec.md`。名称取当前目标，先检查目录避免覆盖另一项工作。文件创建/修改仍须符合当前任务授权。

决策调查票可用以下格式；实施票沿用调用它的 skill 或宿主模板，不强加调查字段：

```markdown
# 01: <问题或任务名称>
Type: grilling
Status: open
Owner: unassigned
Blocked by: none

## Question
<这一票解决什么>

## Acceptance criteria
- <可检查的完成条件>

## Resolution
<未完成时留空；完成时写结果、证据链接及决定链接>
```

本地缺省状态为 open / in-progress / closed；“blocked”由依赖推导，不维护第二套状态。延期或等待用户的票保持未完成并注明原因与恢复条件，不用关闭来清空待办。移出范围或取消应记录真实原因，并同步检查其后继是否仍缺少前提。

依赖使用真实身份或相对具名链接。先建立身份再连边，确认引用存在且图无环；聊天草稿可以临时编号表达关系，明确尚未持久化。

## 前沿与认领

**依赖已满足**指前置提供了本票所需的答案、产物或验收证据；不能只看 closed 标签。取消、拒绝或移出范围是否解除依赖，要看是否真的提供了所需结论，或用户已确认替代方案/取消该依赖；未确认则仍阻塞。调查票解决一个选择，不代表相关代码已实施。

frontier 是范围内未完成、必要前置已满足、没有他人持有的票；本会话已认领且可继续的票不必重新认领。用户指定了阻塞票时先说明前提，可在授权范围内解决前置或做不依赖它的调查，不能把指定等同于依赖已消失。

只读查看不认领、不改状态。需要认领时先重新读取身份、依赖和 owner；Markdown 更新无法保证互斥。存在并发时用一个协调写入者，其他会话只返回证据，或使用支持原子认领的 tracker；不能把普通文件写入称为分布式锁。

本地任务是过程资产，不代替 ADR/Notes。长期决定落在仓库的权威记录，`.scratch` 被清理后仍能检索理由。
