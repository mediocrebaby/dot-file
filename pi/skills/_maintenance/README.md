# Skills 维护与验收

此目录不是可调用 skill，不增加自动入口。共享宿主规则见 [PI-RUNTIME.md](PI-RUNTIME.md)。当前保留 16 个 skill：11 个默认发现入口，5 个仅显式调用入口；业务规则各有一个权威位置。

## 整理原则

- 保留现有命令兼容性。`grill-me`、`grill-with-docs` 是手动快捷入口，不复制访谈规则；是否删除应依据使用习惯，而非仅凭目录数量。
- 不把低频写作偏好搬进常驻指令。`condensed-tech-docs` 保持短小、按需加载，避免节省一个入口却增加每轮上下文。
- 流程按证据与风险分级：排障允许暂定假设引导复现，但未验证不宣称修复；访谈分小组提问；地图按授权范围推进，而非一会话一票。
- 产物服从问题：架构审查默认对话报告，必要时才生成 HTML；原型选择最小可验证形态，不强制 UI。代价是产物形式不再完全统一，需要交付时明确验证与证据位置。
- 领域建模仅在术语、概念边界或关系变化时触发，不跟随所有 ADR 编辑。决定记录与词汇表分工不变。
- Agent 写作指引优先保留可执行动作、授权和完成条件，删除长篇概念论述；代价是教学解释更少，但执行入口更集中。
- spec 优先沿用宿主格式，以行为和验收为核心，不强制用户故事句式、单一测试边界或禁止定位证据。保留手动入口，不拆成多个需要额外导航的小模板。

- 拆票保留已确认拆分，不重复设确认点；纵向切片只贯穿实际涉及的层。新拆分仍需明确草稿/确认状态，依赖重构要有具体理由，不能以提效名义绕过授权。
- 地图与拆票共享 tracker 的身份、依赖和失败恢复规则。closed 不代表所需前提已提供；超时不代表未创建。代价是推进或重试前多一次有针对性的核对，避免错误解阻或重复发布。
- UI 原型围绕所问变量比较，不强制三种布局或浮动条；完整原型入口与副作用必须隔离，而非只隐藏控件。原页面回退与生产隔离需验证，缺环境则明确验证缺口。

前两轮优化指令并增强只读检查器；第三轮集中调整拆票、地图和 UI 原型的关联规则与案例，不更改执行脚本、用户数据格式、全局设置或 Git 提交策略。检查器拒绝原先被忽略的坏案例是防止虚假通过的有意变化。后续优先依据真实偏差补案例、修触发或完成条件，不恢复全场景硬门槛。

## 新会话行为验收

[behavior-cases.json](behavior-cases.json) 为每个入口提供 trigger、skip、expected、must_not；部分入口另有 `additional_cases` 用于分支与授权边界验收。检查器要求每个入口恰有一个主案例，五个主字段均为非空字符串；`additional_cases` 可省略或为空列表，每项必须有非空字符串 `prompt`、`expected`，可选 `must_not` 若存在也必须是非空字符串。损坏 JSON、错误类型、重复或未知入口均报错。主案例只允许上述五个字段与 `additional_cases`；附加案例只允许 `prompt`、`expected`、`must_not`，未知字段报错以防拼写错误导致漏检。新增元数据字段需同步更新检查器和测试。仍需人工检查语义与分支覆盖；结构通过不等于运行过模型。

1. `/reload` 后新开会话，选择一项 trigger 和 skip，用临时项目或只读上下文测试。
2. 对状态转换，准备真实旧 ADR/记录等前置夹具；观察是否检索、是否越权、产物落在哪里。
3. 记录会话/产物路径及实际结果，不用评分猜通过。必须项出现一次违规就列为待修复。
4. 外部发布、API、真实 Word 渲染、桌面 UI 不作为无人值守默认测试；由用户选择隔离环境授权执行。

常用链路：建模/访谈 → decision-notes → 实施/调试/原型证据 → 检查 → 用户请求后提交。写作类 skill 保持职责独立，不为每篇文档创建工程决定。
