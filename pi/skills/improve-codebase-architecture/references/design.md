# 架构审查的本地参考

- Module：承担一项内聚职责的单元；Interface：使用者必须理解的表面。
- Depth：相对较小的接口隐藏有价值的复杂性，不以文件大小或类数量衡量。
- Seam：可以替换依赖或观察行为的真实边界；先使用已有边界，不为测试虚构生产抽象。
- Adapter：隔离外部协议与内部语义；只有一个假想消费者时，不预设通用框架。
- Locality：理解或修改一个行为时，需要跨越多少地方；Leverage：一次结构调整能减少多少后续维护负担。

提出候选前做删除测试：删掉这一层，是把复杂性集中进更清晰的职责，还是仅把复杂性搬家？只有前者是有价值的简化线索。

比较两种接口时，让它们分别处理同一组真实调用、失败和测试场景。记录各自最强理由及代价，允许现状胜出，不为了“两个方案”编造稻草人。候选若违背现行 ADR/Note，说明哪些前提变化使重访合理。
