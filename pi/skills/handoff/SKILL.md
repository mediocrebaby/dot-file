# handoff

把当前会话浓缩成一份「下一个 Claude 拿到就能立刻上手」的交接文档。目标读者是**未参与本次会话的另一个 Claude 实例**，不是人类。

## 输出位置与命名

- **目录**：当前工作目录下的 `./.handoff/`（不存在则创建）
- **文件名**：`<主题>.md`
  - 主题从当前会话内容中提炼，用小写短横线连接，如 `refactor-auth-module.md`、`fix-login-race-condition.md`、`add-handoff-skill.md`
  - 主题要具体到能一眼看懂是哪件事，避免 `task.md`、`session.md`、`work.md` 这种泛化名字
- **冲突处理**：目标文件已存在时，追加时间戳后缀 `<主题>-YYYYMMDD-HHMM.md`，绝不静默覆盖
- **路径分隔符**：Windows 上写入时用 `./.handoff/xxx.md` 或反斜杠均可，工具会处理

写入前用 `ls ./.handoff/ 2>/dev/null` 或 `fd . ./.handoff` 探一下是否已有同名文件。

## 内容结构（严格按顺序输出）

用以下模板，缺失的段落写 `（无）` 而不是删掉标题，方便下一个会话对齐结构：

```markdown
# <会话主题>

> 生成时间：<YYYY-MM-DD HH:MM>
> 工作目录：<当前 cwd 绝对路径>
> 相关分支/commit：<git 分支名 + 短 sha，如果是 git 仓库>

## 1. 任务目标
用户最初想解决什么问题？为什么做这件事？一到三句话讲清。

## 2. 当前状态
现在做到哪一步？用「已完成 / 进行中 / 未开始」三段式概括。

## 3. 关键文件与位置
按 `file_path:line_number` 列出本次会话真正读过或改过的核心文件，附一句用途说明。
只列关键的，不要把 ls 出来的全部文件搬进来。

## 4. 关键决策与原因
本次会话中做出的、会影响后续走向的选择。格式：
- **决策**：选了 X 而不是 Y
- **原因**：因为 ...
- **影响**：后续 Z 需要注意 ...

## 5. 未完成的待办
下一个会话应该接着做什么？按优先级排序，每条包含：
- [ ] 要做的事（具体到能直接动手的粒度）
- 相关文件：`path:line`
- 参考上下文：一句话点明为什么这么做

## 6. 已知问题与坑
本次踩过的坑、还没解决的报错、依赖的外部条件（如需要某个 API key、某个服务未启动）。

## 7. 环境与依赖
- 相关命令：如 `pnpm dev`、`cargo test -- --nocapture`
- 关键环境变量、配置文件位置
- 运行 / 构建 / 测试的入口

## 8. 给下一个会话的建议
一句话开场白：「你接手时，先读 X 再跑 Y，然后从 Z 开始」。
```

## 生成流程

1. **回顾会话**：默读整个对话，识别真正的任务主线，忽略跑题、误操作、被撤销的探索。
2. **提炼主题**：想清楚这个会话如果只能用一个短横线命名的文件名，该叫什么。
3. **探测冲突**：`ls ./.handoff/ 2>/dev/null` 或 `fd . ./.handoff 2>/dev/null`，看目标文件是否已存在。
4. **补齐 git 信息**（如是 git 仓库）：`git rev-parse --abbrev-ref HEAD` 和 `git rev-parse --short HEAD`。
5. **按模板写入**：用 `Write` 工具一次性生成完整文档。
6. **回执**：告知用户文件绝对路径 + 一句话概括写了什么，方便用户 review。

## 内容质量硬要求

- **面向机器**：不要写「我们讨论了...」「用户表示...」这种叙事口吻，直接给事实和指令。
- **可执行 > 可读**：待办要具体到「改 `src/auth.ts:42` 的 `validateToken` 函数，把 `Bearer` 前缀校验去掉」，而不是「优化认证逻辑」。
- **只写真发生的事**：不要凭想象补全「用户可能还想...」「未来可以...」，这类推测放在第 8 段的建议里且明确标注。
- **保留原始报错**：踩过的坑要贴关键报错原文（截取核心行即可），不要转述。
- **别拷贝大段代码**：引用文件位置即可，让下一个会话自己 `read`；只在决策依据必须展示时贴 3–10 行片段。

## 反例

- 文件名叫 `handoff.md` / `session-summary.md` / `notes.md` —— 太泛，换成具体主题
- 把整段 `git log` / 整个 `ls` 输出粘进文档 —— 只保留决策相关的
- 「我帮用户实现了登录功能」—— 改成「已完成：`src/login.ts` 新增 `login()`，走 POST /api/session；待办：加错误处理」
- 静默覆盖已有 handoff —— 必须探测冲突并加时间戳
- 写完不告诉用户路径 —— 必须回执绝对路径
